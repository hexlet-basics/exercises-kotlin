В этом уроке мы изучим пакеты и импорт функций Kotlin. Разберём полные имена, псевдонимы и доступность объявлений верхнего уровня. Мы научимся использовать функции из разных пакетов и разрешать совпадение их коротких имён.

Пакет объединяет объявления под общим именем. Объявление `package` в начале файла определяет пакет для функций и других объявлений этого файла. Полное имя функции складывается из имени пакета и имени самой функции.

Функции можно объявлять непосредственно в файле, вне других функций и типов. Такие объявления называются объявлениями верхнего уровня. Имя пакета помогает отличать одинаково названные функции из разных частей программы.

## Обращение к другому пакету

Представим, что библиотека форматирует подписи пользователей. В ней уже есть функция `shortName`, которую требуется вызвать из программы. Библиотека и программа принадлежат разным пакетам.

Файл _Names.kt_ содержит готовую функцию.

```kotlin
package names

fun shortName(
    first: String,
    last: String,
): String = "$first ${last[0]}."
```

В этом коде полное имя функции имеет вид `names.shortName`. Пример предполагает непустую фамилию, потому что обращается к индексу `0`. Имя файла не добавляется к имени функции при обращении из Kotlin.

В файле _Main.kt_ программа импортирует нужное объявление перед своими функциями.

```kotlin
package report

import names.shortName

fun main() {
    println(shortName("Mira", "Stone")) // Mira S.
}
```

Здесь `import names.shortName` делает короткое имя `shortName` доступным в текущем файле. При вызове передаются обычные аргументы. Без импорта тот же вызов можно записать через полное имя `names.shortName("Mira", "Stone")`.

Пакет задаётся строкой `package`, поэтому он не вычисляется автоматически из каталога или имени файла. В проектах каталоги обычно повторяют структуру пакетов для удобства навигации. Несколько файлов могут содержать одно имя пакета и добавлять в него свои объявления.

## Совпадающие имена

Две библиотеки могут предоставлять функции с одинаковыми короткими именами. Псевдоним после `as` задаёт локальное имя для импорта. Он действует в текущем файле и не переименовывает исходное объявление.

Допустим, одна библиотека формирует короткую подпись человека, а другая формирует подпись документа. Обе экспортируют функцию `title`. Для демонстрации их поведение можно записать в двух отдельных файлах.

В файле _PersonTitle.kt_ находится функция из пакета `people`.

```kotlin
package people

fun title(name: String): String = "Person $name"
```

В этом примере полное имя первой функции равно `people.title`. В файле _DocumentTitle.kt_ другая функция принадлежит пакету `documents`.

```kotlin
package documents

fun title(name: String): String = "Document $name"
```

Здесь имя второй функции равно `documents.title`. Чтобы вызвать обе из одного файла, дадим импортам разные псевдонимы.

```kotlin
package summary

import documents.title as documentTitle
import people.title as personTitle

fun main() {
    println(personTitle("Noa")) // Person Noa
    println(documentTitle("Guide")) // Document Guide
}
```

В этом коде `personTitle` обращается к функции из `people`, а `documentTitle` обращается к функции из `documents`. Каждое короткое имя однозначно связано со своим объявлением. Псевдоним задаёт локальное имя функции. Её параметры и результат остаются такими же, как у исходного объявления.

## Видимость и стандартная библиотека

Объявление верхнего уровня без модификатора видимости доступно из другого пакета. Если перед `fun` записать `private`, функция станет доступной только внутри своего файла. Так можно скрыть вспомогательное вычисление, оставив наружу одну основную операцию.

Например, файл библиотеки содержит функцию подписи и закрытый помощник подготовки имени.

```kotlin
package labels

private fun cleanName(name: String): String = name.trim()

fun label(name: String): String = "User ${cleanName(name)}"
```

В этом примере другая часть программы может импортировать `labels.label`. Импорт `labels.cleanName` компилятор отклонит, поскольку `cleanName` объявлена через `private`. При этом вызов `cleanName` из `label` разрешён, потому что обе функции находятся в одном файле.

Стандартная библиотека тоже состоит из пакетов. Часть её имён импортируется автоматически, поэтому мы пользовались `println`, `String` и строковыми операциями без явных импортов. Импорт делает имя доступным для записи в файле. Установка внешней зависимости решает другую задачу и не выполняется самим ключевым словом `import`.
