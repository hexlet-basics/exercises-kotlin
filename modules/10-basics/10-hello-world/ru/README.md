Kotlin позволяет писать программы с явно заданными типами данных, функциями и собственными типами. В этом курсе мы работаем с Kotlin/JVM. Компилятор переводит исходный код в байткод, который выполняет виртуальная машина Java (JVM). Знание Java для написания такого кода не требуется.

Курс рассчитан на человека, который умеет писать функции, условия и циклы, работает со строками и коллекциями на любом языке. Мы будем переносить эти навыки в Kotlin и разбирать особенности его модели данных. После курса мы сможем обрабатывать коллекции, описывать свои типы и явно работать с отсутствием результата.

## Что проверяет компилятор

При переносе знакомого алгоритма в новый язык приходится учитывать его правила работы с данными. Например, функция может требовать число, а вызывающий код передавать строку. Компилятор Kotlin проверяет такие несоответствия до запуска программы. Мы получаем сообщение с местом ошибки и исправляем исходный код перед выполнением.

Часть проверок приходится писать самостоятельно, например проверку допустимой цены или возраста. Kotlin снимает другую часть работы, проверяя совместимость типов и разрешённые обращения к значениям. Дальше мы увидим, как описать возможность отсутствия значения так, чтобы компилятор требовал её обработать.

На схеме показан путь программы для JVM.

```text
Код Kotlin → Компилятор → Байткод → JVM → Результат
```

Сначала компилятор читает исходный текст и проверяет его. JVM выполняет уже подготовленную программу. Ошибка компиляции останавливает этот путь до выполнения, поэтому при таком отказе мы сначала читаем сообщение компилятора.

## Первая программа

Представим, что небольшая консольная программа сообщает об успешном запуске. Пока не вдаваясь в детали записи, её целиком можно показать так.

```kotlin
fun main() {
    // Сообщение о запуске
    println("Kotlin is running")
}
```

В этом примере программа печатает `Kotlin is running` и переводит строку. Точка входа называется `main`, а `println` выводит переданное значение. Запись текста в двойных кавычках называется строковым литералом. Комментарий после `//` предназначен читателю кода и в вывод не попадает. Этих ориентиров достаточно, чтобы изменить сообщение в первом упражнении. Собственные функции мы разберём отдельно.

В упражнении Code Basics окружение уже готово. Мы меняем код в редакторе и запускаем проверку. Если компилятор сообщает `Unresolved reference`, он не смог найти указанное имя. Например, запись `printn` вместо `println` приводит к такой ошибке. Проверка результата начинается после успешной компиляции и сообщает, совпало ли поведение программы с условием.

## Запуск на своём компьютере

Для самостоятельного запуска понадобятся JDK и компилятор Kotlin. У программы из примера исходный текст находится в файле _hello.kt_. В каталоге этого файла команда компиляции создаёт _hello.jar_ и включает в него библиотеку времени выполнения Kotlin.

```bash
kotlinc hello.kt -include-runtime -d hello.jar
java -jar hello.jar
```

Здесь `kotlinc` собирает программу, а `java` запускает полученный архив на JVM. После запуска мы получаем такое же сообщение, как в примере. Повторять этот путь для упражнений курса не требуется, потому что редактор Code Basics предоставляет окружение для проверки.

## Как построен курс

Мы начнём с типов, функций и управляющих конструкций Kotlin. Затем научимся обрабатывать отсутствующие значения и коллекции, создадим собственные типы. Работа с лямбдами позволит передавать операции в функции и преобразовывать данные средствами стандартной библиотеки.

В заключительной части мы разберём простые обобщения и обработку ошибок. Каждый урок сопровождается отдельной небольшой задачей. Android, серверные фреймворки и корутины потребуют дальнейшего изучения после основ языка.
