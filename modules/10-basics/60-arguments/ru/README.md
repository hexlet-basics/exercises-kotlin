В этом уроке мы изучим именованные аргументы и параметры со значениями по умолчанию. Разберём вызовы с явным указанием имён и пропуском необязательных настроек. Мы научимся задавать понятный контракт функции без повторения одинаковых аргументов.

Параметр описывает вход функции в её объявлении. Аргумент передаёт конкретное значение при вызове. Если мы перечисляем только значения, компилятор сопоставляет их с параметрами по порядку. Именованный аргумент указывает соответствие непосредственно через запись `имя = значение`.

Значение по умолчанию делает параметр необязательным при вызове. Компилятор использует выражение из объявления, если вызывающий код не передал свой аргумент. Обязательные параметры при этом по-прежнему нужно заполнить.

## Имена при вызове

Представим, что программа рассчитывает цену упаковки по числу предметов и цене одного предмета. Два числовых аргумента легко перепутать при чтении, поэтому мы подпишем их имена в вызове.

```kotlin
fun totalPrice(
    count: Int,
    unitPrice: Int,
): Int = count * unitPrice

fun main() {
    println(totalPrice(count = 3, unitPrice = 80)) // 240
    println(totalPrice(unitPrice = 80, count = 3)) // 240
}
```

В этом примере обе записи передают `3` параметру `count`, а `80` параметру `unitPrice`. Когда все аргументы именованы, их порядок можно менять. Имена берутся из объявления функции, поэтому опечатку в имени параметра компилятор обнаружит.

При смешанном вызове удобно сначала передавать позиционные аргументы, затем именованные. Например, `totalPrice(3, unitPrice = 80)` сохраняет понятный порядок. Именованные аргументы особенно полезны, когда несколько соседних параметров имеют один тип.

## Необязательные параметры

Допустим, программа формирует сообщение для журнала. Чаще всего сообщение имеет уровень `INFO`, но иногда вызывающий код выбирает другой уровень. Дадим параметру подходящее значение по умолчанию.

```kotlin
fun logLine(
    message: String,
    level: String = "INFO",
    source: String = "app",
): String = "[$level][$source] $message"

fun main() {
    println(logLine("Started")) // [INFO][app] Started
    println(logLine("Slow query", level = "WARN")) // [WARN][app] Slow query
    println(logLine("Connected", source = "db")) // [INFO][db] Connected
}
```

Здесь `message` остаётся обязательным. В первом вызове функция получает значения `level` и `source` из объявления. Во втором мы заменили только `level`. В третьем передали `source` по имени и сохранили значение `INFO` для пропущенного `level`.

Пропуск аргумента отличается от передачи пустой строки. Вызов `logLine("Started", level = "")` передаёт именно пустую строку и даёт `[][app] Started`. Значение по умолчанию срабатывает при отсутствии аргумента.

## Когда вычисляется значение по умолчанию

Выражение по умолчанию может зависеть от предыдущих параметров. Оно вычисляется при вызове, когда соответствующий аргумент пропущен. Поэтому одно объявление может рассчитывать разные исходные настройки для разных входов.

Например, у прямоугольника вторую сторону можно по умолчанию приравнять к первой. Тогда короткий вызов описывает квадрат, а полный позволяет задать прямоугольник.

```kotlin
fun perimeter(
    width: Int,
    height: Int = width,
): Int = 2 * (width + height)

fun main() {
    println(perimeter(5)) // 20
    println(perimeter(5, 3)) // 16
}
```

В этом коде вызов `perimeter(5)` вычисляет значение `height` по переданному `width`. Ссылка на предыдущий параметр видна прямо в объявлении. Такая запись сокращает вызов и сохраняет единый контракт вычисления.
