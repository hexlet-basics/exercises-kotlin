В этом уроке мы изучим обход коллекций в циклах. Разберём перебор элементов, индексов и записей карты. Научимся накапливать результат обработки в отдельной коллекции.

Цикл `for` умеет последовательно получать элементы коллекции. В записи `for (item in items)` переменная `item` на каждой итерации получает очередной элемент. Индекс для чтения здесь не нужен. У пустой коллекции тело цикла не выполняется ни разу.

Приложение хранит список цен и вычисляет общую стоимость. Для этого достаточно прочитать каждое значение.

```kotlin
fun totalPrice(prices: List<Int>): Int {
    var total = 0
    for (price in prices) {
        total = total + price
    }
    return total
}
```

Начальное значение 0 задаёт результат для пустого списка. Переменная `price` обозначает полученное значение. Изменение отдельной локальной переменной не заменит элемент в исходном списке.

## Когда нужен индекс

Если действие зависит от позиции или меняет сам список, можно перебирать диапазон `indices`. Он содержит допустимые индексы от 0 до `size - 1`.

Уценка меняет цены в переданном списке. Функция уменьшает каждую цену на одну и ту же величину.

```kotlin
fun reducePrices(
    prices: MutableList<Int>,
    discount: Int,
) {
    for (index in prices.indices) {
        prices[index] = prices[index] - discount
    }
}
```

Здесь длина списка остаётся прежней. Добавлять или удалять элементы во время такого обхода опасно, потому что позиции сдвигаются и первоначальный диапазон перестаёт соответствовать содержимому.

## Записи карты

Свойство `entries` предоставляет записи карты. У каждой записи есть `key` и `value`.

Для списка товаров нужно собрать подписи с количеством. Результат хранится отдельно от исходной карты.

```kotlin
fun labels(stock: Map<String, Int>): List<String> {
    val result = mutableListOf<String>()
    for (entry in stock.entries) {
        result.add("${entry.key}=${entry.value}")
    }
    return result
}
```

Пустой изменяемый список создаётся через `mutableListOf<String>()`. Указание типа в угловых скобках помогает компилятору, потому что по пустому набору элементов вывести его нельзя.

Карта как общий тип не обещает порядка записей. Если порядок результата важен, его нужно задать отдельно. У множества тоже нет обещания определённого порядка, но его элементы можно читать тем же `for`.

Во время обычного обхода нельзя добавлять и удалять записи исходной карты или менять размер исходной коллекции. Для отбора, подсчёта и построения другого набора удобно читать исходные данные и записывать результат в отдельную коллекцию. Изменение значений по существующим индексам списка допускается, если его размер сохраняется.
