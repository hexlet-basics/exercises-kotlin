В этом уроке мы изучим наследование классов Kotlin. Разберём открытые классы, переопределение методов и обращение к родительской реализации. Научимся расширять готовое поведение и проверять вызов через базовый тип.

Наследование позволяет определить класс на основе другого класса. Базовый класс предоставляет свойства и методы, а производный класс добавляет или уточняет поведение. Экземпляр производного класса можно передать в функцию, которая ожидает базовый тип.

В Kotlin обычный класс закрыт для наследования. Модификатор `open` явно разрешает создание производных классов. Метод тоже нужно отдельно объявить `open`, если производный класс должен его переопределять.

В приложении доставки обычная посылка считает стоимость по массе. Посылка со срочной доставкой использует базовый расчёт и добавляет фиксированную надбавку.

```kotlin
open class Parcel(
    protected val weight: Int,
) {
    open fun cost(): Int = weight * 10
}

class ExpressParcel(
    weight: Int,
) : Parcel(weight) {
    override fun cost(): Int = super.cost() + 50
}
```

После двоеточия `Parcel(weight)` вызывает конструктор родителя с нужным аргументом. Слово `override` заменяет поведение открытого метода. Выражение `super.cost()` вызывает именно реализацию базового класса и позволяет использовать её результат.

При переопределении сохраняются имя, параметры и совместимый тип результата. Если метод родителя закрыт для переопределения, компилятор отклонит `override`.

## Доступ в производном классе

Модификатор `protected` разрешает доступ внутри класса и его потомков. Внешний вызывающий код такого доступа не получает. Это отличается от `private`, который закрывает член и от производных классов.

Другой способ доставки добавляет плату, зависящую от массы. Он читает унаследованное свойство `weight`.

```kotlin
class HeavyParcel(
    weight: Int,
) : Parcel(weight) {
    override fun cost(): Int = super.cost() + weight * 2
}
```

Здесь в производном классе не объявляется второе свойство `weight`. Аргумент конструктора передаётся родителю, а метод обращается к уже сохранённой массе через разрешённый `protected` доступ.

## Вызов через базовый тип

Переопределённый метод выбирается по фактическому объекту, даже если переменная имеет базовый тип.

```kotlin
fun shipmentCost(parcel: Parcel): Int = parcel.cost()

fun main() {
    val regular: Parcel = Parcel(3)
    val express: Parcel = ExpressParcel(3)
    println(shipmentCost(regular)) // 30
    println(shipmentCost(express)) // 80
}
```

Это называется динамическим выбором метода. Общий код знает только `Parcel`, а поведение определяется созданным экземпляром. Для небольшого расширения достаточно одного уровня наследования. Общий контракт без совместного состояния и реализации можно выразить знакомым интерфейсом.
