В этом уроке мы изучим интерфейсы Kotlin. Разберём общий контракт свойств и методов и его реализацию в классах. Научимся работать с разными объектами через один тип.

Несколько классов могут решать одну задачу разными способами. Вызывающему коду часто достаточно знать, какую операцию они поддерживают. Интерфейс задаёт такой общий контракт. Класс, реализующий интерфейс, обязан предоставить заявленные свойства и методы.

Сам интерфейс не создаёт отдельный объект и не хранит состояние экземпляра. Свойство интерфейса обозначает требование к чтению или записи. Его данные хранит реализующий класс либо вычисляет getter.

В приложении печатаются подписи разных объектов. Общий контракт требует название и текст подписи.

```kotlin
interface Described {
    val title: String

    fun description(): String
}

class Book(
    override val title: String,
    private val pages: Int,
) : Described {
    override fun description(): String = "$title ($pages pages)"
}
```

Двоеточие после объявления класса указывает на реализацию `Described`. Ключевое слово `override` отмечает выполнение требования интерфейса. Конструктор `Book` сразу предоставляет свойство `title`, а метод `description()` вычисляет подпись из данных экземпляра.

## Работа через общий тип

Функция с параметром типа интерфейса принимает любой экземпляр его реализации. Ей не нужно знать остальные свойства класса.

Другой вид объекта хранит имя автора и формирует подпись по своему правилу.

```kotlin
class Article(
    override val title: String,
    private val author: String,
) : Described {
    override fun description(): String = "$title by $author"
}

fun printDescription(item: Described) {
    println(item.description())
}
```

Вызовы `printDescription(Book("Guide", 120))` и `printDescription(Article("News", "Ada"))` используют один контракт. При обращении `item.description()` выполняется метод соответствующего объекта. Это позволяет добавлять реализации, сохраняя общий вызывающий код.

Через переменную типа `Described` доступны только члены, объявленные в интерфейсе. Даже если фактический объект хранит число страниц, контракт не разрешает читать его напрямую.

## Готовая реализация метода

Интерфейс может дать реализацию метода через другие члены своего контракта.

```kotlin
interface Named {
    val name: String

    fun greeting(): String = "Hello, $name"
}

class Visitor(
    override val name: String,
) : Named
```

`Visitor` хранит имя, а метод `greeting()` получает из интерфейса. При необходимости класс может переопределить его через `override`. Поля состояния в интерфейсе не появляются, потому что текст приветствия вычисляется из предоставленного свойства.
