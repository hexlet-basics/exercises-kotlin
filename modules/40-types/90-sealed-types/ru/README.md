В этом уроке мы изучим закрытые семейства типов Kotlin. Разберём варианты с собственными данными и без данных. Научимся обрабатывать все варианты через исчерпывающий `when`.

Перечисление задаёт фиксированные константы с общей структурой. Когда разные случаи несут разные данные, удобнее описать их отдельными типами под общим контрактом. Модификатор `sealed` сообщает компилятору, что набор прямых реализаций контролируется внутри модуля и пакета.

Закрытый интерфейс объявляется как `sealed interface`. Вариант с данными можно описать классом данных, а вариант без данных можно представить единственным объектом. Общий тип принимает любой такой вариант, сохраняя информацию о его конкретном устройстве.

Сервис проверяет доступность книги. Успех содержит число доступных экземпляров, отказ содержит причину, а ожидание пока не содержит результата.

```kotlin
sealed interface Availability

data class Available(
    val count: Int,
) : Availability

data class Rejected(
    val reason: String,
) : Availability

object Pending : Availability
```

Экземпляр `Available(3)` хранит количество, а `Rejected("closed")` хранит текст. Для `Pending` создавать экземпляр через скобки не нужно. Эти значения можно передавать через параметр типа `Availability`.

## Выбор и уточнение типа

Внутри `when` проверка `is` выделяет вариант с данными. После неё smart cast разрешает обращаться к свойствам этого варианта. Объект без данных можно указать в ветви напрямую.

```kotlin
fun availabilityText(result: Availability): String =
    when (result) {
        is Available -> "copies=${result.count}"
        is Rejected -> "rejected=${result.reason}"
        Pending -> "pending"
    }

fun main() {
    println(availabilityText(Available(3))) // copies=3
    println(availabilityText(Rejected("closed"))) // rejected=closed
    println(availabilityText(Pending)) // pending
}
```

Ветви охватывают все прямые варианты. Компилятор разрешает выражение без `else`. Если в семейство добавится ещё одна реализация, он потребует дополнить обработку. Это помогает сохранить связь между набором состояний и действиями для каждого состояния.

## Когда нужен закрытый набор

Обычный интерфейс позволяет добавлять реализации независимо от кода, который использует контракт. Закрытое семейство выбирают, когда обработчик должен знать все варианты. Оно подходит для состояний операции или результатов проверки, у которых заранее определён конечный набор случаев.

`sealed interface` сам не создаёт объекты и не добавляет общего хранилища данных. Каждый класс или объект сохраняет своё содержимое. В примерах этого курса все прямые реализации находятся в одном файле. В реальном проекте они должны оставаться в одном модуле и пакете.

Nullable-тип описывает отсутствие одного вида значения. Закрытое семейство может различать несколько причин и состояний, передавая данные каждого случая. Выбор зависит от того, сколько разных исходов действительно требуется обработчику.
