В этом уроке мы изучим классы данных Kotlin. Разберём сравнение экземпляров и получение изменённой копии. Научимся учитывать свойства конструктора и общие вложенные объекты.

Когда объект нужен прежде всего для хранения данных, часто требуется сравнивать его содержимое и получать новые версии записи. Модификатор `data` поручает компилятору создать подходящие операции автоматически. Они используют свойства, объявленные в первичном конструкторе.

В каталоге хранится название книги и её цена. Два отдельно созданных объекта с одинаковыми данными должны сравниваться как равные записи.

```kotlin
data class Book(
    val title: String,
    val price: Int,
)

fun main() {
    val first = Book("Kotlin", 500)
    val second = Book("Kotlin", 500)
    println(first == second) // true
    println(first === second) // false
    println(first) // Book(title=Kotlin, price=500)
}
```

Для класса данных компилятор создаёт `equals()` и согласованный с ним `hashCode()`. Оператор `==` использует `equals()`, поэтому сравнивает свойства `title` и `price`. `===` продолжает проверять ссылку на один экземпляр. Метод `toString()` даёт показанное представление для вывода и диагностики.

Первичный конструктор класса данных должен иметь хотя бы один параметр. Каждый его параметр объявляется как свойство через `val` или `var`. Свойства, добавленные только в теле класса, в автоматически созданное сравнение не входят.

## Изменённая копия

Метод `copy()` создаёт новый экземпляр. Для его параметров по умолчанию используются значения свойств исходного объекта. Именованные аргументы позволяют заменить нужные части.

```kotlin
fun main() {
    val regular = Book("Kotlin", 500)
    val discounted = regular.copy(price = 450)
    println(regular.price) // 500
    println(discounted.price) // 450
    println(regular === discounted) // false
}
```

Исходный объект сохраняется. Такой способ удобен, когда несколько частей программы используют одну запись, а одна операция должна получить её обновлённую версию. Даже вызов `copy()` без аргументов создаёт отдельный экземпляр с теми же значениями.

## Поверхностное копирование

`copy()` копирует значения свойств, включая ссылки на вложенные объекты. Он не создаёт независимую копию всего содержимого по цепочке ссылок.

У подборки есть изменяемый список меток. При копировании подборки список остаётся общим.

```kotlin
data class CollectionInfo(
    val title: String,
    val tags: MutableList<String>,
)

fun main() {
    val original = CollectionInfo("Books", mutableListOf("public"))
    val changed = original.copy(title = "Guides")
    changed.tags.add("kotlin")
    println(original.tags) // [public, kotlin]
    println(original.tags === changed.tags) // true
}
```

Это называется поверхностным копированием. Верхние объекты разные, а вложенный список один. `val tags` запрещает заменить ссылку, но не закрывает изменение `MutableList`. Поэтому при выборе данных для `data class` нужно учитывать, какие объекты останутся общими после `copy()`.
