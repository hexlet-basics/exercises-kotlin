В этом уроке мы изучим сортировку коллекций средствами Kotlin. Разберём естественный порядок и сравнение по нескольким свойствам. Научимся получать упорядоченный результат и выбирать, нужно ли менять исходный список.

Порядок элементов часто задаёт отдельное требование к результату. Для чисел естественным служит порядок по величине, а для строк используется лексикографическое сравнение. Функция `sorted` возвращает новый список в таком порядке.

Предположим, мы получили номера кабинетов в порядке их загрузки. Для таблички нужен список по возрастанию, но исходные данные должны сохранить прежний порядок.

```kotlin
fun main() {
    val rooms = listOf(204, 101, 103)
    val ordered = rooms.sorted()
    println(ordered) // [101, 103, 204]
    println(rooms) // [204, 101, 103]
}
```

Для записей с полями общего порядка может не быть. Функция `sortedBy` принимает лямбду, которая выбирает сравниваемое значение. Например, `words.sortedBy { it.length }` упорядочит строки по длине.

## Несколько признаков

Представим, что занятия нужно поставить в расписание по дню недели, а внутри дня по времени начала. Одного признака здесь недостаточно. Сначала создадим правило сравнения через `compareBy`, затем добавим второй признак через `thenBy`.

```kotlin
data class Lesson(
    val day: Int,
    val startHour: Int,
)

fun main() {
    val lessons = listOf(Lesson(2, 14), Lesson(1, 12), Lesson(1, 9))
    val order = compareBy<Lesson> { it.day }.thenBy { it.startHour }
    val schedule = lessons.sortedWith(order)
    println(schedule) // [Lesson(day=1, startHour=9), Lesson(day=1, startHour=12), Lesson(day=2, startHour=14)]
}
```

`compareBy<Lesson>` получает готовый тип записи как аргумент типа. Этот вызов создаёт объект с правилом сравнения, который передаётся в `sortedWith`. Свои обобщённые функции для этого объявлять не требуется. Второй признак используется только при равенстве первого. Дополнительный `thenBy` может добавить следующий уровень сравнения.

Если значения всех признаков равны, сортировка сохраняет взаимный порядок соответствующих элементов. Это свойство называют стабильностью сортировки.

## Сортировка на месте

Для изменяемого списка есть операция `sort`, которая переставляет элементы в самом объекте и возвращает `Unit`.

```kotlin
fun main() {
    val values = mutableListOf(3, 1, 2)
    val sameList = values
    values.sort()
    println(values) // [1, 2, 3]
    println(sameList) // [1, 2, 3]
}
```

Обе переменные ссылаются на один список, поэтому изменение видно через каждую из них. Выбор между `sorted` и `sort` определяется контрактом функции. Если вызывающий код должен сохранить порядок своих данных, возвращаем новый результат. Пустой список и список из одного элемента уже упорядочены.
