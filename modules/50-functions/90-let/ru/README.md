В этом уроке мы изучим преобразование значения через `let`. Разберём доступ к аргументу лямбды и сочетание с безопасным вызовом. Научимся выполнять преобразование только для присутствующего значения.

Функция `let` передаёт свой получатель в лямбду и возвращает результат её последнего выражения. Это позволяет собрать небольшой расчёт рядом со значением, которое он использует. Внутри лямбды объект доступен как обычный аргумент, например через имя `it`.

Представим, что во входных данных указан необязательный номер комнаты. Для присутствующего номера нужна подпись с добавленным префиксом, а отсутствие номера должно сохраниться.

```kotlin
fun roomLabel(number: Int?): String? = number?.let { "Room $it" }

fun main() {
    println(roomLabel(12)) // Room 12
    println(roomLabel(null)) // null
}
```

Оператор `?.` проверяет, есть ли значение. Для `12` он вызывает `let`, и параметр лямбды имеет тип `Int`. Для `null` вызов не выполняется, а всё выражение возвращает `null`. Тип результата `let` определяется последним выражением блока, здесь это `String`. С учётом безопасного вызова тип всего выражения равен `String?`.

## Именованный аргумент блока

Когда расчёт длиннее одного выражения, аргументу можно дать имя. Промежуточные переменные остаются внутри блока.

Допустим, приложение принимает необязательную метку устройства. При наличии метки мы убираем лишние пробелы и строим подпись с длиной очищенного текста.

```kotlin
fun deviceLabel(raw: String?): String? =
    raw?.let { text ->
        val cleaned = text.trim()
        "[$cleaned] ${cleaned.length}"
    }

fun main() {
    println(deviceLabel("  AX  ")) // [AX] 2
    println(deviceLabel(null)) // null
}
```

Лямбда возвращает строку, которую сформировало её последнее выражение. Объект слева от точки не становится результатом автоматически. Вызов `let` может вернуть значение другого типа.

Оператор Элвиса можно добавить после выражения с безопасным вызовом, если по контракту вместо отсутствия нужен запасной результат. Например, `roomLabel(null) ?: "No room"` даст строку `"No room"`.

## Где проверяется null

Сам `let` не пропускает `null`. Это делает безопасный вызов перед ним. Вызов через обычную точку выполнит лямбду и для nullable-получателя.

```kotlin
fun main() {
    val text: String? = null
    val length = text.let { it?.length ?: 0 }
    println(length) // 0
}
```

Здесь тип `it` остаётся `String?`, поэтому внутри снова нужен безопасный доступ. Выбор между `?.let` и `.let` зависит от того, следует ли выполнять блок при отсутствии значения. Для короткой цепочки обычных обращений часто достаточно уже знакомого `?.`, без дополнительного блока.
