В этом уроке мы изучим классы с параметром типа. Разберём тип свойства, создание экземпляра и сохранение типа при извлечении значения. Научимся описывать контейнер для разных видов данных.

Если устройство объекта не зависит от конкретного вида хранимого значения, тип этого значения можно сделать параметром класса. Тогда каждый экземпляр сохраняет данные согласованного типа. Компилятор проверяет и запись, и последующее чтение с учётом выбранного аргумента типа.

Представим, что приложение хранит результат вместе с признаком проверки. Сам результат бывает строкой или числом, а обёртка в обоих случаях устроена одинаково.

```kotlin
class CheckedValue<T>(
    val value: T,
    var checked: Boolean = false,
)

fun main() {
    val word = CheckedValue("ready")
    val number = CheckedValue(42)
    val text: String = word.value
    val count: Int = number.value
    word.checked = true
    println(text) // ready
    println(count) // 42
    println(word.checked) // true
}
```

Имя `T` объявлено после имени класса и доступно в конструкторе, свойствах и методах. В первом вызове компилятор выводит тип `CheckedValue<String>`, во втором `CheckedValue<Int>`. К чтению `word.value` не требуется добавлять приведение, потому что тип строки сохранён в типе контейнера.

## Явный тип и nullable-значения

Аргумент типа можно записать в вызове конструктора. Это полезно, если начальное значение не даёт достаточных сведений для выбора желаемого типа.

```kotlin
class CheckedValue<T>(
    val value: T,
    var checked: Boolean = false,
)

fun main() {
    val missing = CheckedValue<String?>(null)
    val value: String? = missing.value
    println(value) // null
}
```

Сам контейнер существует, хотя его свойство содержит `null`. Тип `CheckedValue<String?>` отличается от `CheckedValue<String>?`. В первой записи nullable относится к содержимому, во второй к самому контейнеру. Для чтения свойства nullable-контейнера нужен безопасный доступ.

## Связь с обобщённой функцией

Функция, принимающая такой объект, может объявить собственный параметр типа и связать его с типом контейнера.

```kotlin
class CheckedValue<T>(
    val value: T,
    var checked: Boolean = false,
)

fun <T> readChecked(container: CheckedValue<T>): T? = if (container.checked) container.value else null

fun main() {
    val result = readChecked(CheckedValue(12, checked = true))
    println(result) // 12
}
```

Вызов выбирает `T` из аргумента функции. Тип `Int` проходит через `CheckedValue<Int>` к результату `Int?`. Такое объявление сохраняет сведения о данных без ручного приведения после чтения. Разные экземпляры контейнера могут хранить разные типы, но выбранный тип каждого конкретного экземпляра определяется его объявлением и вызовом конструктора.
