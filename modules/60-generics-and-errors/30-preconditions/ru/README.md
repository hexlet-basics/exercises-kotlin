В этом уроке мы изучим проверки аргументов и состояния перед выполнением операции. Разберём генерацию исключений через `throw`, функции `require` и `check`. Научимся останавливать недопустимое действие и пояснять причину отказа.

У функции могут быть ограничения на допустимые аргументы. Объект также может разрешать действие только в определённом состоянии. Если продолжение нарушило бы эти условия, выполнение нужно прервать до изменения данных. Исключение передаёт управление вызывающему коду вместе с объектом, описывающим причину отказа.

Предположим, мы рассчитываем стоимость аренды по числу дней. Нулевое или отрицательное число дней считается ошибкой вызова.

```kotlin
fun rentalPrice(days: Int): Int {
    if (days <= 0) {
        throw IllegalArgumentException("Days must be positive")
    }
    return days * 100
}

fun main() {
    println(rentalPrice(3)) // 300
}
```

`throw` создаёт особый путь завершения. При ошибке функция не возвращает обычное значение, а выражение `days * 100` не вычисляется. Если вызывающий код не обработает исключение, ошибка передаётся выше по цепочке вызовов. Текст сообщения помогает установить, какое условие было нарушено.

## require и check

Для проверки аргумента подходит `require`. Он принимает логическое условие и выбрасывает `IllegalArgumentException`, если условие ложно. Для ошибки текущего состояния объекта подходит `check`, который выбрасывает `IllegalStateException`.

Представим, что таймеру задают положительную длительность, а запускать его повторно нельзя. Проверим длительность в блоке `init`, а состояние перед запуском в методе.

```kotlin
class Timer(
    val seconds: Int,
) {
    var running: Boolean = false
        private set

    init {
        require(seconds > 0) { "Seconds must be positive" }
    }

    fun start() {
        check(!running) { "Timer is already running" }
        running = true
    }
}

fun main() {
    val timer = Timer(10)
    timer.start()
    println(timer.running) // true
}
```

Лямбда после `require` или `check` создаёт сообщение. Она вызывается только при нарушении условия. Проверки выполняются до изменения состояния, поэтому неуспешный вызов `start` не должен частично запускать таймер. Повторный вызов сообщит `IllegalStateException`, а создание `Timer(0)` сообщит `IllegalArgumentException`.

## Тип Nothing

Выражение, которое всегда завершает выполнение исключением, не получает обычного результата. Для такой функции можно указать тип `Nothing`.

```kotlin
fun reject(message: String): Nothing = throw IllegalArgumentException(message)

fun requireName(value: String?): String = value ?: reject("Name is required")
```

`Nothing` отличается от `Unit`. Функция с результатом `Unit` может успешно закончиться, а функция с результатом `Nothing` не возвращает управление обычным способом. Благодаря этому компилятор принимает вызов `reject` там, где иначе ожидалось бы строковое значение. Из этого пути строка никогда не будет получена.
