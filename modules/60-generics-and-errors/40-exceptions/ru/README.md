В этом уроке мы изучим обработку исключений через `try` и `catch`. Разберём результат выражения `try` и выполнение завершающего блока `finally`. Научимся обрабатывать ожидаемый отказ и сохранять распространение посторонних ошибок.

Исключение прерывает обычное выполнение и поднимается по цепочке вызовов. Вызывающий код может окружить операцию блоком `try` и обработать определённый тип ошибки в `catch`. После обработки выполнение продолжается за этой конструкцией.

Предположим, готовая функция принимает код режима и выбрасывает исключение для неизвестного кода. В интерфейсе требуется показать запасное название только при таком отказе.

```kotlin
fun modeName(code: Int): String {
    require(code == 1 || code == 2) { "Unknown mode" }
    return if (code == 1) "quiet" else "fast"
}

fun safeModeName(code: Int): String =
    try {
        modeName(code)
    } catch (error: IllegalArgumentException) {
        "unknown"
    }

fun main() {
    println(safeModeName(1)) // quiet
    println(safeModeName(9)) // unknown
}
```

Блок `catch` получает объект исключения в параметре `error`. В этом примере текст сообщения не нужен, поэтому параметр не используется. `try` служит выражением. При успехе его результат задаёт последнее выражение основного блока, а при обработанном отказе результат задаёт последнее выражение соответствующего `catch`.

## Граница обработки

Тип в `catch` задаёт, какие ошибки обработчик способен исправить. Здесь ожидается `IllegalArgumentException`. Если внутренняя операция выбросит `IllegalStateException`, этот обработчик не подойдёт, и ошибка продолжит подниматься к вызывающему коду.

Перехват общего `Exception` скроет и те отказы, для которых запасной результат не предусмотрен. Обработчик должен соответствовать соглашению конкретной операции. Kotlin не требует перечислять все возможные исключения в сигнатуре функции.

## Завершающее действие

Блок `finally` выполняет действие после основного блока или обработчика. Он выполняется и при необработанном исключении. Это позволяет освободить захваченный ресурс или отметить завершение операции независимо от результата.

Допустим, после попытки построить подпись нужно записать отметку о завершении. В примере выведем её на экран.

```kotlin
fun modeName(code: Int): String {
    require(code == 1 || code == 2) { "Unknown mode" }
    return if (code == 1) "quiet" else "fast"
}

fun main() {
    val result =
        try {
            modeName(9)
        } catch (error: IllegalArgumentException) {
            "unknown"
        } finally {
            println("Attempt finished")
        }
    println(result) // unknown
}
```

Сначала появится строка `Attempt finished`, затем `unknown`. Последнее выражение `finally` не задаёт результат `try`. Если код внутри `finally` сам выбросит исключение, оно может заменить исходный результат или первоначальную ошибку, поэтому завершающее действие тоже требует подходящего контракта.

Для обычного разбора строки в число по-прежнему подходит `toIntOrNull`. Обработка исключений нужна там, где сама вызываемая операция использует исключение как способ сообщить об отказе.
